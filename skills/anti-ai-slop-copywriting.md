# Anti-AI-Slop Technical Copywriting Specification

A practical standard for drafting high-converting, human-grade cover letters, portfolio blurbs, and recruiter responses.

---

## The Core Rule: Verifiable Metrics Over Buzzwords

Recruiters and engineering managers discard applications filled with generic AI jargon. Every claim must follow this concrete pattern:

$$\text{Action Verb} + \text{Target System / Module} + \text{Verifiable Metric / Result} + \text{Tech Stack}$$

### ❌ The "AI-Slop" Pattern (Generic & Discarded)
> "I am a passionate and dynamic Full-Stack Developer excited to leverage my cutting-edge skills to craft robust, innovative, and seamless solutions for your next-generation product."

### ✅ The Human-Grade Pattern (High-Signal & Interview-Winning)
> "Over the past 2 years, I designed and maintained a multi-tenant SaaS platform serving 20+ live client deployments, architected 38 relational PostgreSQL models using Prisma ORM, and integrated an automated QRIS payment webhook engine handling instant checkout reconciliation."

---

## Forbidden Vocabulary (Strict Blacklist)

Never use these words or their variations in cover letters, form essays, or outreach emails:

| Forbidden AI-Slop Word | Why It Fails | Recommended Human Alternative |
|---|---|---|
| `passionate` | Overused platitude; conveys zero technical skill | Describe what you actually built and debugged |
| `innovative` | Subjective fluff; show, don't tell | Explain the technical constraint solved |
| `cutting-edge` | Meaningless buzzword | Name the exact tool/framework version |
| `seamless` | Systems are rarely seamless in production | "Low-latency", "fail-safe", "ACID-compliant" |
| `robust` | Vague adjective | "Handled 10k daily reqs with automated retry" |
| `dynamic` | AI placeholder | "Multi-tenant", "event-driven", "parameterized" |
| `leveraging` | Classic corporate AI tell | "Using", "implementing", "integrating" |
| `crafting` | Pretentious phrasing for code | "Engineering", "developing", "deploying" |
| `revolutionize` | Unrealistic hyperbole | "Streamlined", "automated", "reduced latency by" |
| `game-changer` | Sales fluff | "Cut manual order reconciliation time in half" |

---

## 4 Golden Rules for Application Copy

1. **Specific Project Attribution**: Name the actual application type (e.g. ERP internal system, multi-tenant SaaS, API token gateway) rather than vague "various web projects".
2. **Respect Vertical Truths**: If an application asks about a niche domain you have not worked in (e.g. Core Banking, SIMRS Hospital Systems), admit zero direct domain experience while pivoting to analogous architectural experience (e.g. strict transactional ACID compliance, double-entry ledgers, RBAC).
3. **Calibrated Conciseness**: Keep cover letters strictly between 100 and 160 words. Recruiters review hundreds of resumes; a tight, 2-paragraph pitch with verified links outperforms a wall of text.
4. **Active Live Links**: Point recruiters to live production URLs with HTTP 200 status codes rather than dead localhost references or raw code snippets.
